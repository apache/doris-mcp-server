# 迁移到 1.0.0

[English](1.0.0.md) | 简体中文

1.0 有意移除了 1.0 以前的直接 Tool Surface，不提供 Alias 窗口。Server 升级必须
和 Host Schema Cache、Authorization Scope、Protocol Revision 与部署配置一起
规划。

兼容路径 [docs/migration-1.0.0.md](../migration-1.0.0.md) 仍会进入 sdist；本文是
扩展后的运维版本。

## 迁移前盘点

升级前记录：

- 当前包版本与 MCP 协议版本；
- Transport 与 Endpoint；
- Prompt/Agent/代码使用的全部旧 Tool 名称；
- Host 是否支持 Progressive Disclosure；
- Static/JWT/OAuth/Doris OAuth 模式与 Scope；
- Doris 路由、账号、Patch 与所需 FE/BE HTTP 访问；
- ADBC、Lineage、Ossie、MetricFlow 或自定义 Provider 依赖；
- Result/Time/Concurrency Limit；
- 回滚 Package 与配置。

不能只升级 Server，却让 Host 保留 1.0 以前的缓存 Schema。

## 破坏性合同变化

- 1.0 以前顶级 Tool 不再注册或调用。
- 默认暴露变成 8 个 Hierarchical Domain。
- Flat 回退使用 `doris_query_execute_query` 等正式名称。
- 精确 Child Discovery/Execution Scope 替代旧 Scope/Wildcard。
- Runtime Availability 与 `manifest_version` 进入调用合同。
- 5 个 Table Metadata Call 合并到 `get_table_context` Section。
- ADBC 进入 `doris_query`。
- ADBC 默认关闭，要求用户明确指定并传 `explicit_adbc=true`；普通 SQL 继续使用
  `execute_query`。
- Semantic Model-specific Call 要求精确 `model_ref`。
- `doris_semantic` 新增 8 个 MetricFlow Consumer Child，并保持 MetricFlow 编译与
  MCP 受治理 Doris 执行分离。
- 现代 HTTP 在 `/mcp` 使用无状态 MCP `2026-07-28`。
- `/mcp/legacy` 默认关闭，且不会恢复 Tool 名称。
- `doris_admin` 仍不可用。

## 选择暴露模式

首选：

```bash
export MCP_TOOL_EXPOSURE_MODE=hierarchical
```

Host 注册：

- `doris_catalog`
- `doris_query`
- `doris_cluster`
- `doris_pipeline`
- `doris_search`
- `doris_governance`
- `doris_lakehouse`
- `doris_semantic`

它用 `{}` 调用选中领域，再使用精确 `child_tool`、`arguments` 和当前
`manifest_version` 调用同一个 Tool。

Host 不能完成两步流程时：

```bash
export MCP_TOOL_EXPOSURE_MODE=flat
```

重启 Server 并重连 Host。Flat 会消耗更多上下文，仍必须使用 1.0 正式名称。

## Table Context 合并

| 旧调用 | `get_table_context` Section |
|---|---|
| `get_table_basic_info` | `basic` |
| `get_table_schema` | `schema` |
| `get_table_comment` | `comments.table` |
| `get_table_column_comments` | `comments.columns` |
| `get_table_indexes` | `indexes` |

`schema` 为必需。可选 Section 独立返回 Status/Source/Warning；以前只消费一个无
限定 Success Object 的调用方需要调整。

## Host 变更

1. 删除缓存 Tool Definition 与 Prompt 中写死的旧 Signature。
2. 选择 Exposure Mode 后重启/重连。
3. 调用 `tools/list`，只注册返回合同。
4. Hierarchical 模式实现 Empty-object Discovery。
5. 使用返回的精确 Child Schema，不凭记忆构造参数。
6. 支持时保留并发送 `manifest_version`。
7. 遇到 `CHILD_MANIFEST_STALE` 重新发现。
8. 把 `callable=false` 与 Reason Code 当作操作状态。
9. 保留 Structured Result Metadata、Warning 与 Truncation。
10. 停止解析原始 Backend Error String。

## Authorization 迁移

- 用精确 Domain/Child Scope 替换旧 Tool Scope。
- 分开发现与执行 Grant。
- 显式启用可选 Semantic/Doris OAuth Channel。
- Doris OAuth 使用精确 `domain.child` Allowlist。
- 使用实际请求身份重新测试 Negative Scope 与 Doris RBAC。
- 不能为了弥补 MCP Scope 缺失而授予宽权限 Doris 服务账号。

OAuth Manifest 可能因用户不同而不同。一个 Principal 发现的 Manifest/Cursor 不能
被另一个身份复用。

## 协议迁移

HTTP `2026-07-28`：

1. 每个 `POST /mcp` 发送一个自包含 JSON-RPC 请求；
2. `_meta` 包含协议版本、Client Capability 与 Client Identity；
3. 增加必需 `MCP-Protocol-Version`、`Mcp-Method` 与命名调用 `Mcp-Name`；
4. 移除 `initialize`、`notifications/initialized`、`Mcp-Session-Id`、Sticky
   Session、HTTP GET Stream、Last-Event-ID 和 Resumable SSE 假设；
5. 接受现代 Structured Content 与类型化错误。

有界旧 HTTP 迁移可以启用 Adapter，只让旧 Client 连接 `/mcp/legacy`。经过回归
测试的 HTTP Profile 是 `2025-06-18`（包括 Dify 1.16.1）和 `2025-11-25`。
不能把旧流量发到 `/mcp`；Adapter 保留 1.0 Tool 与安全合同，不是 1.0 以前的
兼容 Alias。

## Doris 版本与能力迁移

- 最低 Doris 版本为 `2.0.0`。
- 能力决策只使用归一化 `major.minor.patch`。
- RC/GA Suffix、Commit Hash 与 Deployment Hint 只用于诊断。
- 版本范围满足后，仍需要 Runtime Probe/Provider/Permission。
- Doris 4.0.6+ Native Lineage 需要健康可查询 Provider/Store；4.0.6 以前 Audit
  为主要路径，之后为 Degraded Fallback。
- Certification 与 Runtime Support 分离，不能把 `target_uncertified` 硬编码为
  不可用。
- ADBC 在 2.0 不可用，2.1+ 进入版本范围；2.1.0-2.1.4 在 Provider 和 Endpoint
  实时探测前先标为 Degraded。
- Variant 查看从 2.1 开始，ANN/向量/混合检索从 4.0 开始，后续特征独立 Gate。

## 配置迁移

- 使用 `MCP_TOOL_EXPOSURE_MODE`，不配置旧 Tool Bucket。
- Client 迁移后保持 `ENABLE_LEGACY_HTTP_ADAPTER=false`。
- 独立 Replica 配置共享 `MCP_STATE_HANDLE_SECRET`。
- 保持 `MCP_ADMIN_DOMAIN_ENABLED=false`。
- 验证非回环 Authentication 与 Host/Origin Policy。
- Doris OAuth 要求 HTTP、`WORKERS=1` 且关闭外部 OAuth。
- 使用显式 Optional-provider 路径与上限。
- 检查 Row、Byte、Timeout、Concurrency 与 Query-security Limit。

## 分阶段发布

1. 在隔离环境与目标 Doris 账号上部署 1.0。
2. 验证 `/live` 与 `/ready`。
3. 从 Host 运行 `server/discover`、`tools/list`、全部 Domain Discovery 和正式
   Read-only Query Child。
4. 验证同一对话从 Catalog 切换 Cluster。
5. 执行 Write、Scope、Doris Permission、Stale-manifest、Cursor、Timeout、Row、
   Byte 负向测试。
6. 验证 Optional Provider 与 Degraded Path。
7. 迁移一个 Host Profile，监控类型化错误。
8. 移除 Legacy Endpoint 使用，再关闭 Adapter。
9. 推广到其他 Host，并删除旧 Schema Cache/Config。

## 回滚

- Server Package/Image 与对应配置一起回滚。
- 重启所有 Host 并重新发现。
- 不能把 1.0 Manifest/Cursor 用于 1.0 以前进程。
- 只有旧 Server 真正恢复时才恢复旧 Prompt/Scope。
- 记录 Gate 失败原因，不能长期混用新旧 Tool 名称。

## 验收清单

- [ ] Host 按预期看到 8 Domain 或精确 55 Formal Child。
- [ ] 普通 SQL 不会在缺少明确用户意图时选择 ADBC。
- [ ] MetricFlow Compile-only 与 MCP 执行路径保持执行边界。
- [ ] 1.0 以前名称均不可发现/调用。
- [ ] Catalog Discovery 与 Table Context 可用。
- [ ] Query Read-only Guard 与 Bounds 可用。
- [ ] Cluster Capability Status 能解释不可用 Child。
- [ ] 精确 Authorization 与 Doris Negative Permission Test 通过。
- [ ] MCP `2026-07-28` 在必需 Transport 可用。
- [ ] 迁移后关闭 Legacy Adapter。
- [ ] Optional Provider Fail Closed 且诚实报告状态。
- [ ] Production Health、Log、Trace 与 Rollback 已验证。
