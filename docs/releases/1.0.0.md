# Apache Doris MCP Server 1.0.0 release notes

[English](1.0.0.md) | [简体中文](1.0.0.zh-CN.md)

**Release tag:** `1.0.0`  
**Published:** 2026-08-01  
**Protocol baseline:** MCP `2026-07-28`  
**Minimum Apache Doris version:** `2.0.0`

The detailed GitHub release record is
[[RELEASE] Apache Doris MCP Server 1.0.0 Release](https://github.com/apache/doris-mcp-server/issues/189).
The packaged compatibility note remains at
[docs/release-notes-1.0.0.md](../release-notes-1.0.0.md).

## Summary

Version 1.0 establishes the first stable public architecture for connecting
MCP Hosts and AI agents to Apache Doris. It replaces the pre-1.0 collection of
independent direct tools with one capability-aware, read-only contract:

- eight stable top-level domains;
- fifty-five exact child capabilities;
- deterministic progressive discovery and flat fallback;
- runtime version, feature, provider, route, and permission evidence;
- exact schemas, authorization identifiers, and typed result/error envelopes;
- MCP `2026-07-28` over Streamable HTTP and stdio;
- bounded, fail-closed security and reliability behavior.

The MCP protocol contract is GA on the supported transports. The Python
package remains classified Beta because some distributed deployment modes are
intentionally constrained.

## Architectural change

The default Host sees only eight complete problem domains. It calls a domain
with `{}` to receive the full authorized child manifest and exact schemas, then
calls the same domain with an exact child and arguments.

This is deterministic progressive disclosure, not probabilistic Server-side
intent routing. A model can switch from Catalog to Cluster in one conversation
because all domains remain registered. Hosts without two-step support can use
the startup-time `flat` mode and receive the same children under formal names.

One catalog drives hierarchical mode, flat mode, authorization, handler
binding, generated documentation, and tests. Pre-1.0 names are removed without
an alias window.

[tool registry](../tool-registry.md) for all child names and bindings.

## Capability-aware discovery

Every authorized child receives structured availability based on:

- normalized Doris three-part version and component vector;
- live SQL/metadata/HTTP probes;
- deployment mode and route coherence;
- optional provider readiness/generation;
- exact MCP permissions and Doris visibility;
- configured safety policy.

Discoverable unavailable children remain visible with `callable=false` and a
stable reason code. Unauthorized children are hidden. A route/provider/
permission generation change invalidates `manifest_version` and requires
rediscovery.

Real version comments such as
`Doris version doris-3.0.3-rc03-... (Cloud Mode)` normalize to `3.0.3` for
capability/certification. RC/GA text and commit metadata do not create separate
support results.

## MCP `2026-07-28`

- One SDK v2 protocol core for stdio and Streamable HTTP.
- Stateless, self-contained modern requests.
- Optional `server/discover` and deterministic product identity.
- Required modern `_meta` and HTTP header consistency.
- Bounded paginated lists with principal/scope/snapshot-bound HMAC cursors.
- Bounded JSON Schema 2020-12 definitions, arguments, and structured outputs.
- Sanitized W3C trace-context propagation.
- Honest subscription boundary: no `subscriptions/listen` without a real
  cross-worker event source.
- Default-off isolated `2025-11-25` HTTP migration adapter at `/mcp/legacy`.

## Security

- Static bearer token, JWT, external OAuth/OIDC, and Doris-backed OAuth
  boundaries.
- Exact MCP operation, domain discovery, and child execution scopes.
- Request-specific Doris OAuth/static-token/global connection routing.
- Doris RBAC remains final for metadata and data visibility.
- Central read-only SQL/identifier/parameter guard.
- Query timeout, row, byte, complexity, collection, and schema ceilings.
- Result masking and sensitive metadata/error redaction.
- Host/Origin, trusted proxy, non-loopback authentication, and HTTP destination
  policy.
- Digest-only managed token persistence and protected token-management
  boundary.
- Explicit allowlisted custom providers; no silent code loading.
- Reserved `doris_admin` domain remains unregistered.

## Reliability

- Separate `/live` and Doris-backed `/ready` semantics.
- Route-aware connection pools, cancellation disposal, health recovery, and
  multi-FE candidates.
- Private capability TTL/cache/singleflight and bounded stale fallback.
- Deterministic stale/unavailable/invalid/timeout/execution error classes.
- Partial success only for explicitly optional evidence sections.
- Output Schema validation before response delivery.
- Request ID, duration, source, warnings, truncation, and sanitized tracing.
- Explicit native/fallback paths for cluster, search, lakehouse, and lineage.

## Native lineage and semantic consumers

Doris 4.0.6+ may use canonical events from a companion producer and queryable
lineage store. Native mode requires live provider/store evidence. Bounded audit
inference is the primary path before 4.0.6 and an explicit degraded fallback
afterward when native evidence is unavailable.

The optional Semantic domain consumes reviewed Apache Ossie models for
read-only grounding. Every model-specific operation requires exact
`model_ref`; private Doris bindings remain Server-side. The integration does
not author models or compile/execute semantic expressions.

MetricFlow integration adds eight exact-model consumer children for model
status, metrics, group-bys, saved queries, dimension values, compilation, and
execution. The optional provider compiles Doris SQL only; all execution returns
to the MCP Query runtime for read-only validation, route/RBAC selection,
limits, audit, redaction, and schema validation.

## Breaking changes

- Removed all pre-1.0 direct names and aliases.
- Defaulted to hierarchical exposure.
- Introduced formal flat names and exact scopes.
- Added manifest availability and stale-generation handling.
- Consolidated five table calls into `get_table_context` sections.
- Moved ADBC under Query.
- Made ADBC default-off and callable only with explicit user intent plus
  `explicit_adbc=true`; ordinary SQL remains on `execute_query`.
- Required exact `model_ref` for semantic calls.
- Added eight MetricFlow consumer children with a compile-only sidecar boundary.
- Standardized modern HTTP on MCP `2026-07-28` at `/mcp`.
- Kept legacy protocol and administration boundaries isolated/default-off.

Read [Migrating to 1.0](../migration/1.0.0.md) before upgrading.

## Release verification

The release gate includes:

- warnings-as-errors unit, integration, protocol, security, and deployment
  tests;
- protocol/authentication/core-manager coverage floors;
- Ruff, Mypy, Bandit, and lock verification;
- generated 8/55 catalog drift checks;
- source distribution and clean-wheel installation;
- official MCP `2026-07-28` stateless conformance;
- stdio and Streamable HTTP process tests;
- hierarchical/flat and cross-process catalog stability;
- real Apache Doris read-only calls and negative permission tests.

PR [#187](https://github.com/apache/doris-mcp-server/pull/187) prepared the
tag. PR [#188](https://github.com/apache/doris-mcp-server/pull/188) subsequently
migrated the opt-in real Doris regression suite to the formal 1.0 surface
before the later 8/55 semantic expansion.

## Known limitations

- Doris-backed OAuth state is process-local and requires one worker.
- ADBC is default-off, explicit-only, and fail-closed on token-bound routes.
- Ossie integration is optional, read-only grounding only.
- MetricFlow requires an operator-supplied Doris-capable compiler provider;
  no native MetricFlow/dbt Doris adapter is bundled.
- Native lineage delivery is asynchronous best effort and provider-dependent.
- Audit lineage/dependency inference is bounded and may be incomplete.
- Subscription/change notifications remain unavailable.
- Public reverse-proxy Host/Origin shapes require deployment-specific review.
- Only Doris 4.0.5 is certified at this release boundary.
